## Release notes text (draft for the GitHub release body)

mlx-omarchy v0.7.7

Changes since v0.7.6:

Default models
- Everyday is now Qwen3.5-9B (4-bit) + Laya; Compact is Qwen3-4B-Instruct-2507
  (4-bit) + Laya; Quality stays Qwen3.8-27B (4-bit) + Laya and needs 96 GB.
  The 2B left the catalog: on the fixed stack it measured last on every
  quality proxy (0/8 native cards, GSM8K 11/20, IFE 17/20) while the 9B and
  4B hold the 2.0 s first-text budget (1.05 s and 0.66 s p95; 0.78 s and
  0.44 s on the real card prompt).
- GDN prefill fix: the 9B composed per-token fallback is replaced by the
  fused route — prefill 46.8 to 316.9 tok/s on the M2 Max.
- Decode attention: the hd128 decode window is measured at {1, 7168}; the
  compatibility rows track it.

Cards
- Cards ship via markdown promotion; `card_format` stays unset. The
  fenced-JSON schema was measured and rejected: the 4B wrote 18/18 cards but
  first-text p95 rose to 2.40 s, and the 9B produced one spurious card.
- Held-out card suite (frozen v4): 9B 16/18 with 0 spurious, 4B and 27B
  18/18 with 0 spurious — pass at the pre-registered 15/18 bar.

Routing
- Automatic decision routing stays off. The frozen policy scores precision
  1.000 and recall 1.000 with 0 of 15 injection cases routed, but the Laya
  head call runs at p95 347 ms against the 250 ms warm deadline; routing
  waits on which latency the gate measures. Explicit Compare options is
  unaffected.

Voice input (GPU)
- Recognition runs on the GPU worker: WER 3.42% test-clean, 2.92%
  test-other, 4.39% accented, 11.43% in 0 dB babble (192-clip corpus), 0
  CPU-stream dispatches. Empty transcripts fixed: 0 of 96 in the browser
  run, p95 1397.8 ms. One caveat: a 30.04 s clip is cut at the product's
  30.0 s limit; counted as a refusal, test-clean is 8.15%.

Speech output
- The real-time threshold is not met for either engine (Kokoro compiled RTF
  0.743 vs 0.735 eager). Voice as a whole stays unqualified.

System install
- `install.sh --system` stages the /usr tree offline from vendored,
  hash-locked wheels (36 wheels, about 441 MB) for a PKGBUILD, with
  launchers, a systemd user unit, a desktop entry, and a retire command.
  Every install path comes from one name table
  (`serve/mlx_omarchy_paths.py`, generated `packaging/paths.sh`). The
  packaged Honeykrisp ICD is preferred and the packaged Mesa SHA is pinned.

Engine and packaging
- Upstream MLX pin moves 59d600b5 to 9c3d35571a (17-patch series rebased;
  SDPA and GDN VJPs land as fallbacks; contract decode digests
  bit-identical on both chips tested).
- mx.compile: a nested eval can no longer reach a settled tape.
- Stable releases now carry the aarch64 cp314 wheel (built natively on
  Apple Silicon with glslc and the pinned whole-encoder ANE bundle), the
  x86_64 cp311 wheel, the vendored wheel tarball for the system install,
  and a SHA256SUMS covering all assets. Releases are gate-verified as
  drafts before they are published.

Known limits
- Two card-reply defects are open and under root-cause: on the 4B a card
  request returned an empty reply (status=complete, no text); on the 9B a
  card turn returned status=stopped with partial text. The 27B is not
  affected.
- Quality (27B) misses the 2.0 s first-text budget through the assistant
  API (2.5-14.4 s on card turns); prefill runs at 73-81 tok/s with both
  workers resident (75-85% of the alone-on-GPU rate).
- Automatic routing off; speech output real-time unmet; 16 GB tier fit is
  arithmetic on measured 96 GB peaks — no 16 GB machine was measured.
- Long-context admission still needs measured workspace and latency curves
  per chip and runtime.

Driver requirement (Apple Silicon, Omarchy): the Honeykrisp fork driver
stays required as the active Vulkan ICD; wheels ship kernels, not the
driver. See docs/install-omarchy.md.
