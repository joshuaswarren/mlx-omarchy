## Gate 1 — uploaded-asset verification

`python3 scripts/verify-release-assets.py v0.6.3 --repo joshuaswarren/mlx-omarchy`
→ **VERIFIED: every uploaded asset matches what the release claims**
(exit 0). Per asset: sha256 matches the release notes, version consistent
across filename/dist-info/METADATA, recorded build commit `1ed1dab`
matches the tag (found in libmlx.so, CMake, METADATA, RECORD), feature
strings correct for a stable build (control `MLX_DISABLE_COMPILE`
present, profiling harness absent), platform tags agree.

One procedure note: the verifier pairs a hash to an asset by finding a
64-hex token within 300 chars AFTER the asset name in the notes. The
first notes draft used the `hash  name` SHA256SUMS column order, which
mis-paired and correctly FAILED the gate; reordering to
`name`-then-`hash` fixed it. The gate catching a notes-pairing bug is
the gate working.
