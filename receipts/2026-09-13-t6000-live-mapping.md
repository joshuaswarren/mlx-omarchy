## Result

The M1 Max ANE exists in the live Apple Device Tree (ADT), but the Linux FDT does not describe an ANE device or its DART. Linux therefore creates no ANE platform device, `/dev/ane*`, or `/sys/class/ane`, and the driver cannot bind. The live evidence now identifies the ANE and DART physical candidates, raw interrupt, raw DART SID property, memory-related properties, and PMGR ancestry. It does not yet prove all Linux binding semantics, so no DTS was generated or applied.

This is a mapping draft, not an address guess. Every address below comes from the captured live ADT after its `arm-io` range translation. Raw ADT values are kept separate from Linux binding values.

## Linux FDT absence and infrastructure

The live FDT has:

- no node name matching `ane*`;
- no compatible `ane,t*` or `apple,t*-ane`;
- no `reg-names = "engine"`;
- no `interrupt-names = "ane"`;
- no ANE DART at the live ADT addresses listed below;
- an AIC2 provider at `interrupt-controller@28e100000`, compatible `apple,t6000-aic`, with four interrupt cells;
- PMGR providers `ane_sys` and `ane_sys_cpu`, described below.

The current ANE module requests:

| Driver consumer | Required Linux property |
| --- | --- |
| `devm_platform_ioremap_resource_byname(pdev, "engine")` | one `reg` entry named `engine` |
| `platform_get_irq_byname(pdev, "ane")` | one translated interrupt named `ane` |
| `of_count_phandle_with_args(..., "power-domains", ...)` and `dev_pm_domain_attach_by_id` | at least one ordered Linux genpd phandle |
| `iommu_get_domain_for_dev()` | a provider-attached IOMMU domain, normally created from `iommus` |

The diagnostic `ane.ko` matches the running kernel and advertises `apple,t6000-ane`, but it remains unloaded because no matching FDT node or ANE DART provider exists. Loading it would not bind and would not qualify the hardware.

## AIC mapping

The live Linux FDT identifies `interrupt-controller@28e100000` as `apple,t6000-aic` with `#interrupt-cells = <4>`. The kernel binding defines the cells as interrupt type, die ID, interrupt number, and flags. This proves the required Linux tuple shape for T6000. The live ADT provides raw numbers `0x302` for ANE and `0x303` for its DART, but it does not provide the Linux trigger flags or a reviewed ADT-to-FDT interrupt conversion. The mapping therefore records the raw numbers and die-0 context without inventing a completed interrupt specifier or `interrupt-names` assignment.

## PMGR suppliers

The live ADT resolves ANE power gate `0x1cf` to PMGR device `ANE-SYS-V`, whose parent is `ANE_SYS_CPU`.

The live Linux FDT already contains the upstream supplier chain at `power-management@292280000`:

```text
afr              power-controller@1e8  phandle 0xa8
  -> ane_sys     power-controller@268  phandle 0x18, power-domains = <0xa8>
       -> ane_sys_cpu power-controller@2c8, power-domains = <0x18>
```

The matching kernel source labels are `ps_ane_sys` and `ps_ane_sys_cpu` in `t600x-pmgr.dtsi`. The ADT leaf `ANE-SYS-V` is not present as a Linux provider. The exact list and order that the ANE node must place in `power-domains` therefore remain unresolved; the existing supplier chain is evidence, not permission to substitute a parent for the missing leaf.

## Memory and firmware ownership

The live ANE node contains:

- `pre-loaded = 1`;
- `asc-dram-mask = 0x1f000000000`;
- segment names `__TEXT;__DATA`;
- a 64-byte `segment-ranges` property;
- `function-mcc_dataset = <0x7d, "M$DS">`.

These fields prove firmware-managed memory metadata exists. They do not prove a Linux `reserved-memory`, `memory-region`, `dma-ranges`, or DMA-coherency contract. The current driver consumes none of those properties. The mapping must not claim that reserved memory is unnecessary until a T6000 firmware or ADT-to-FDT rule explains the preloaded segment path.

## Next concrete binding work

The next source change must be based on a reviewed T6000 ADT-to-FDT translation for three remaining conversions: ANE range naming, DART `sids` decoding, and the `ANE-SYS-V` PMGR leaf. The AIC conversion must also supply source-backed trigger flags. After those conversions exist, the first DTS change should remain disabled, compile with schema validation, and be inspected for named resources, IOMMU attachment, and genpd suppliers before any module load. No register access or module load should occur until the resulting node can bind all four driver consumers.
