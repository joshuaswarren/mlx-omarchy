Tag: `v0.7.5` (annotated) on commit `937a3352b`, which is `origin/main` head
(`docs: record listener check for the aiden voice and the installer release gap`).
Published as a **PRERELEASE**; v0.7.4 remains the promoted latest. The release
exists so the one-line installer ships the MLX Chat assistant again: the
installer fetches `serve/mlx_omarchy_assistant/*` from the latest release tag,
and v0.7.4 predates that package, so a fresh install aborted with HTTP 404 at

elementwise-add fix (`omp_binary_op_type`,
`overlay/mlx/backend/omarchy/primitives.cpp`) and the Qwen3-TTS codec speech
fix with its focused regression (`tests/test_qwen3_tts_codec_regress.py`).

## Anonymous-access blocker — installed-from-release gates PENDING

The gate battery (clean `install.sh` from the published tag in a throwaway
home on the project M2, GPU matmul smoke, assistant launcher, offline Everyday
pair chat + compare, TTS codec regression on the installed wheel, provenance
line beside measurements) has NOT run: every anonymous fetch of this account's
content is currently answered HTTP 404 by GitHub, so the installer cannot
fetch the tag's `install.sh`, patches, serve files, `SHA256SUMS`, or wheel
without credentials. Evidence, all observed 2026-09-29 ~13:05–13:35 UTC:

- `raw.githubusercontent.com/joshuawarren/mlx-omarchy/{main,v0.7.4,v0.7.5}/…`
  → 404 from four hosts on two networks (dev box, two Linux laptops, the
  reference Mac, whose resolver returns the correct Fastly addresses), with a
  GitHub edge request id in the response (`x-github-request-id`).
- `https://github.com/joshuawarren/mlx-omarchy/releases/download/v0.7.5/SHA256SUMS`
  → 404; `codeload.github.com/.../tar.gz/refs/tags/v0.7.5` → 404.
- Unauthenticated `api.github.com/repos/joshuawarren/{mlx-omarchy,ane-linux-experiments}`
  → `404 Not Found`, while control repos under other owners (octocat,
  omarchy-mac, can1357) answer 200/301 from the same hosts.
- Authenticated API (owner token) reports the repo `private: false`,
  `visibility: public`, and the contents API serves the tag's files — the
  account's public content is hidden from logged-out callers only, which is
  the account-flag/review pattern. Authenticated raw fetches also 404, so
  even credentialed mirror-based gate runs are not possible without changing

Because every installed-from-release gate must run against the PUBLISHED
assets exactly as a fresh user fetches them, none of gates 1–4 and 6 can run
until anonymous access is restored (owner action: GitHub Support appeal for
the account flag). The release stays a prerelease; promotion is blocked by the
same condition (the promotion check itself is an anonymous fetch of
`releases/latest` and a raw HEAD on the tag's `pairs.py`). No gate was
weakened or skipped by substitution; the tree-side pre-gates that could run
(stamp, features, version stability, asset verification) all pass.
