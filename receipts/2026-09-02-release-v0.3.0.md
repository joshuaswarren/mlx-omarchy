## Network anomaly observed during verification (not a release defect)

Plain unauthenticated `https://github.com/.../releases/download/...` returns HTTP 404 from this
LAN egress, and the release page itself 404s unauthenticated — but so do the v0.2.0 release page
and the v0.3.0-alpha.1 asset URL, which have worked for users since 2026-08-31/09-01. A
third-party fetcher (r.jina.ai) also saw 404 on both pages. Authenticated API calls from the dev
box return 200 with correct bytes; `api.github.com/rate_limit` is 200 unauthenticated;
`raw.githubusercontent.com` is 200; GitHub status reports All Systems Operational. jwm1's
authenticated asset fetch also 404'd while the dev box's identical call returned 200. Pattern:
requester-side 404s from GitHub's abuse layer on flagged egress IPs, not a property of this
release. The published bytes were verified through the authenticated asset route with matching
sha256 on both platforms. Worth one browser check from a normal user session; nothing here
indicates the release page or assets are broken for regular users.
