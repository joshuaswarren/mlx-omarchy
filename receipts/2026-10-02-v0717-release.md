# 2026-10-02 — mlx-omarchy v0.7.17 release (supersedes v0.7.15 and v0.7.16, neither published)

Release: https://github.com/joshuaswarren/omarchy-mlx/releases/tag/v0.7.17

**v0.7.17 SUPERSEDES TWO UNPUBLISHED CUTS.** Both were caught by the draft
gate battery BEFORE any publish; both tags stay pushed and burned:
- `v0.7.15` (`c8c576c43`): release-lane serve file list missed
  `perf_placement.py` → ModuleNotFoundError at serve startup on every
  user install (found by w71 on a user-style install).
- `v0.7.16` (`6999e6469`): fixed the installer but carried a function-scope

No asset of either cut was ever published; the v0.7.15/v0.7.16 draft
releases were deleted pre-publication. Also shipped in the cut window:
`4c59e3fa7` (community-data: diagnostics blocks never reject a submission;
collector prints full 4xx bodies).

## Why v0.7.15 was burned

The release lane of install.sh staged `serve/mlx_omarchy_serve/` from a
hardcoded per-file list that lacked `perf_placement.py` (imported by the
serve shim at startup, added by 6c48ae2a9) — every user-style install died
at serve startup with `ModuleNotFoundError: No module named
'perf_placement'`. The `--system` lane (whole-dir copy) was fine; the
defect was release-lane-only. Reproduced on the M2 against the v0.7.15
draft install before the fix. Fixed on main in `6999e6469`:
- `perf_placement.py` and `export_fit_table.py` (also unshipped) added to
  the serve file list;
- new contract test `test_installer_per_file_lists_cover_the_source_trees`
  pins EVERY per-file installer list against its source tree (CONTRACT.md/
  README stay in-repo; `ids_probe.py` documented as a bench-only,
  env-gated exception) — this class cannot regress;
- `packaging/PKGBUILD.example` check() smoke imports
  `mlx_omarchy_serve.perf_placement`;
- release gate 1 now runs the serve shim's exact import pair from the
  installed home on every release (SERVE_ENTRY_EXIT is required 0), and
  was proven to FAIL on the broken v0.7.15 draft install before the fix.

  (#25); server-side tolerance already live for older collectors

  build-time runtime asset checker + clearer seal diagnosis (ab4364b51).
  Note: the v0.7.10 and v0.7.14 release assets are internally consistent;
  the mismatch seen on one machine came from a locally swapped libane.

  default, `MLX_OMARCHY_QUEUE_PRIORITY=low` default); in-shader Cody-Waite
  sin/cos range reduction (6cbf55d8f) replacing the per-call GPU sync
  gate; conv k-tap GEMM scratch cap env
  `MLX_OMARCHY_CONV_GEMM_MAX_SCRATCH_BYTES`.
- **Kokoro engine**: measured real-time on the project M2 (direct RTF
  ~1.2, serve path RTF ~1.5 median over 16 sentences, WER 4.44% set,
  first audio 2.3–6.6 s); NOT the default engine, not qualified pending
  owner listening. Qwen3-TTS (default) unchanged RTF ~0.23.
- **Serve**: `MLX_OMARCHY_UCLAMP_MIN` placement (measured +1–2% prefill on
  jw16/jwm1 idle, zero regression, digests exact).
- **Assistant**: voice accessibility fixes (7 defects); Quality
  token-count admission fix; #17 refactors (no behavior change);
  **startup fix** — `signal` stays the module-level import in the
  entrypoint (a function-scope import made every launch raise
  `UnboundLocalError`; caught by gate 2 on the v0.7.16 draft).
