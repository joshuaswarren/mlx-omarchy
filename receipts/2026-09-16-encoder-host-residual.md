# O(n²) bookkeeping — identical bytes, encoder 8999.6 to 7987.3 ms median

6.45 s non-ANE encoder time on the `83de2255` baseline). Verdict: **LAND.**
The residual is halved (−1158 ms bucket, warm A/B) and the encoder median
drops −1012.3 ms with the program byte-for-byte unchanged: `encoder_hidden`

## Where the residual actually was

cProfile of one warm encoder leg on the release wheel (jwm1, 9.31 s total
under the profiler, pin held):

- `run()`'s own bytecode: **1.40 s** — dominated by the per-statement release
  scan `for name, last in list(self.last_use.items())`: 3351 executed
  statements each rescanning the full live-name map (~2000 entries), O(n²)
  in the statement count.
- `eval_const`: **0.71 s** over 1977 const statements — blob materialization
  (`mx.array` uploads of the 1.2 GB fp16 constants, genuine work) plus
  re-parsing of the const attrs string.
- `execute` + `apply` + parse helpers: **≈0.2 s combined.**

That killed the compile option: the residual is Python bookkeeping in the
interpreter loop, not MLX graph construction — `mx.compile` of the leftover
GPU segment would have carried byte-risk without touching the bucket. The
per-statement MLX op build is already ~µs.

## The cut

Three parse-time precomputations in `overlay/tools/coreml/vulkan_encoder.py`,
no change to any op, order, or value:

1. `Statement.operands` — each statement's operand-name list resolved once in
   `_last_use()` (same `_operand_names` logic, same order), so `ensure()`
   stops re-running the kwargs string scan on every resolution.
2. `EncoderRunner.releases` — names grouped by last-use index, so `run()`
   retires each name at exactly its last-use statement instead of rescanning
   every live name per statement. Deletion semantics are identical: the old
   scan's `last <= stmt.index` collapses to the exact-index group because a
   name's value exists from its producer onward and protected names were
   never deletable. `self.last_use` is no longer mutated during the run
   (that mutation only fed the scan).
3. `Statement.const_kwargs` — the const attrs string parsed once in
   `_parse()`; `eval_const` reads it.

Plus one guard: `_parse` raises `EncoderRunError` if the statement index
sequence is not dense `0..n-1` — an early draft of this change dropped the
`index += 1` and the collapsed indices silently emptied `values` through the
release path; the guard turns that class of parse corruption into a hard
error instead of a plausible wrong run.
