## Fresh-install installer defects found by the clean-run gate (jwm1)

Two pre-existing defects, both fixed on the release branch (the tag was
re-cut twice so the stamps match; the release had zero consumers and
latest stayed on v0.7.2 throughout — first published directly, then
marked prerelease per Main, finally promoted on gate pass):

1. `install.sh` executed the curl-fetched `apply-mlx-lm-patches.sh`
   directly; `curl -o` writes 0644, so any machine without a +x copy
   from an older installer generation failed with Permission denied
   (af1222e44: invoke via `bash`).
2. The apply script resolved its patches dir as `dirname($0)/..`
   (repo layout); installed at `$PREFIX` root that resolved to
   `$HOME/.local/share/patches` and failed every fresh install
   (5738e29ec: find `patches/` beside the script in both layouts).
   Both layouts re-tested on fresh venvs; machines with leftover files
   from older generations had masked both defects (v0.7.2's installer
   carries them too).
