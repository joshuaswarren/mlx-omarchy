## What shipped

Two bugs broke a fresh install of MLX Chat from v0.7.5, both fixed in
`06711ad81` ("laya: fix fresh-install setup, offline and online"):

1. **A fully cached raw Laya snapshot never counted as present.** The
   generic snapshot-completeness check required a top-level `config.json`,
   which Laya's layout (`encoder/config.json`, `tokenizer/`) does not have.
   Offline setup on a fresh home refused with "no raw snapshot to convert".
   Laya now declares its own files and is checked against them, and offline
   refusals name the missing files
   (`serve/mlx_omarchy_serve/__main__.py` snapshot_gaps/hf_layout,
   `serve/mlx_omarchy_assistant/pairs.py`).
2. **The pinned Laya commit `1c5edc17` no longer exists upstream** (Hugging
   Face returns "Invalid rev id"), so a fresh ONLINE download failed. The
   catalog now pins upstream `main` at
   `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`. All five files conversion
   reads hash identical to the earlier conversion, so the converted artifact
   and its weights hash `891102d3…` are unchanged.

Tests: `tests/test_assistant_pairs.py` covers the fully-cached-offline
conversion and the named-gap refusal without network (fails on the v0.7.5
code, passes on the fix).

### Harness script fixes (not product changes)

Two gate-script bugs were made and fixed before the passing runs; both are
harness-only, no pass condition changed:

- The fresh-user online script first pointed at
  `<venv>/bin/mlx-omarchy-chat`, which does not exist — the installer puts
  the launcher in `<throwaway>/.local/bin/`. The launcher never started;
  the run was invalid and was rerun after the path fix.
- The codec regression first ran as a skip-pass (`exit 0` with
  `skipped=2`): the installed venv has no pytest, and
  `MLX_OMARCHY_TTS_TEST_PACK` was unset. A skip-pass is not a run — the
  same defect class the v0.7.5 battery already recorded. Fixed by running
  with the stdlib unittest runner (matching the v0.7.5 harness) and setting
  `MLX_OMARCHY_TTS_TEST_PACK` to the pinned local voice pack; after the fix
  both tests executed on hardware with zero skips.

## Driver requirement on Apple Silicon (Omarchy)

This wheel requires the Honeykrisp fork driver (`joshuaswarren/mesa-1`,
branch `honeykrisp-omarchy`) as the active Vulkan ICD. See
[docs/install-omarchy.md](https://github.com/joshuaswarren/mlx-omarchy/blob/main/docs/install-omarchy.md). Wheels ship kernels, not the driver.
