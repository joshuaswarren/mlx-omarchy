# Private ANE runtime

The ANE runtime strictly validates a schema-3 bundle, copies the manifest and every payload into sealed memory files, validates those exact immutable bytes again, and starts `mlx-omarchy-ane-worker` as a separate process. The worker receives only the sealed descriptors. Its readiness reply must match the graph hash, raw manifest hash, and payload-collection model hash validated by the parent. The worker owns the canonical `joshuaswarren/omarchy-ane` handles, mapped buffers, kernel bindings, and ordered program dispatch. The parent process owns host staging and the control socket. There is no Vulkan, CPU, or simulated fallback inside this runtime.

Build with `MLX_OMARCHY_ANE_SOURCE_DIR` set to a clean checkout at `f261a6cb537aca62f267ad3d01beda0d6877544c`. Configuration fails for another commit or a dirty tracked tree. The worker is installed in `CMAKE_INSTALL_FULL_BINDIR`; build-tree callers use the generated worker path.

Call `AneRuntime::load(bundle, startup_deadline, diagnostic_path)` with a positive deadline and a writable diagnostic path. One absolute monotonic deadline covers validation, snapshotting, process start, and readiness. `execute` requires the exact input names and byte counts declared by the bundle. The worker keeps program handles, physical input/output allocations, state, and intermediate buffers alive across calls. It resets outputs and intermediates for each execution, packs logical fp16 tensors with the declared NCHW plane and row strides, executes every program in `dispatch_plan` order, and copies only declared graph outputs back to the parent.

Every execute and shutdown transaction also uses one absolute monotonic deadline. A failure before command submission closes the control channel without claiming a hardware recovery requirement. A completion timeout, `ane_exec` error, or uncertain shutdown marks the runtime unusable, writes the diagnostic receipt, sends no signal to the worker, and requires a host reboot before more ANE submissions. Live child processes are handed to a nonblocking process-lifetime reaper, so a timed-out API call returns without losing eventual `waitpid` ownership. This avoids interrupting a possibly in-flight kernel or reproducing the known allocator and wait hazards.

`shutdown` clears all worker-owned program handles, waits for process exit within its deadline, and returns the worker PID and released-program count. Callers must treat a failed shutdown as uncertain; only a returned receipt confirms release.

The worker accepts only Linux AArch64 with `apple,t8103-ane`, device-tree status `okay`, driver version `f2a3e5e+lifecycle6`, a bound `ane` platform driver, runtime PM `on/active`, and readable/writable `/dev/accel/accel0`. Its runtime identity records the graph hash, raw manifest hash, payload-collection model hash, kernel, module source version, libane commit, and driver ABI.
