## Status terms

- native: one omarchy kernel or engine path dispatches the operation.
- composed: the operation assembles on the device from several dispatched kernels, or mlx composes core ops because use_fallback returns true.
- named-error: eval_gpu raises `omarchy::unsupported` and the run stops with that qualifier.
- shared-gpu: the primitive has no omarchy entry, and upstream's shared `backend/gpu/primitives.cpp` resolves it generically — zero-copy buffer views or the omarchy copy engine. It counts as covered only when a TEST_CASE anchors it.
- not implemented (nothing runs): upstream MLX defines the primitive, the omarchy backend has no entry for it, and the shared GPU layer has no eval_gpu for it either.
- Dtypes marked `*` pass the capability gates listed under the kernel families.
- `{name}` in a constraint stands for the dispatched operation name.
